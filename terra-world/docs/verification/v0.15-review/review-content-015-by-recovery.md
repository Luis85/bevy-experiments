## Reviewed behavior and evidence

- `render_scenes.rs` resolves a catalog-specific vehicle binding before the generic vehicle kind and only accepts a vehicle model hint for a Vehicle actor. `model_for_anchor` obtains the model from the shared public/private transport appearance API. Rendering never replaces ownership, model authority or collision state. The existing procedural fallback remains until ready hierarchy validation succeeds.
- `render_animation.rs` projects the admitted living-body velocity onto the actual heading to obtain signed forward/reverse speed. Each instance owns f64 wheel phase; the binding's scale adjusts radius. Pause returns before clip, blend, wheel phase, heading history or steering mutation. Rest rotations and local steering parents are preserved. Manual steering uses the currently possessed owned vehicle; autonomous/public steering uses admitted heading change and known catalog wheelbase. It writes imported child transforms only.
- `asset_pack.rs` keeps model, object, all-clip/all-sampler and aliased-channel ceilings. The new wheel policy is bounded to 2–8 wheels, at most 4 steering pivots and a finite radius; named nodes must be distinct and existing. It rejects nonunit wheel ancestry, nested rolling/steering pivots, unsupported animated ancestors and conflicts in unused clips. Runtime admission adds rolling plus steering channel work to the largest selected clip and counts all animated nodes. These are reservation estimates, not hardware claims.
- Optional vehicle policy serializes away when absent. New model targets are explicitly documented as requiring a 0.15 reader while original kind/species packs remain valid. Independent SHA-256 comparison against the retained 0.14 source manifest found all 8 selected wildlife pack/recipe inputs unchanged. The original normalized default-pack identity has a dedicated passing transport regression in the owner's retained test log.
- The generated Comet has four ordinary wheel pivots with separate front steering parents, empty cabin geometry and no authority/occupancy behavior. Independent `generate.py --check` matched all four outputs: 91 nodes, 78 meshes, 210,148 GLB bytes, SHA-256 `e13f7026ad6bee911f52c664e480cfd5f42a3417d2ecd463ea755b7ce72479c4`. No generated source was rewritten.
- `driving.rs`, `interface.rs` and `interaction.rs` use the same actual scene resolution for the Garage fixed-livery rule. Browsing a different showroom model cannot select the rule for the owned car. Queued paid paint consumes an exact displayed context (principal, restore revision, vehicle/model/paint and garage), rechecks the current registry, visibility and ordinary service/cash requirements, then submits the unchanged authoritative command. Generic vehicle overrides disable paid paint; unrelated human overrides do not. Procedural paint and saved paint remain intact. Duplicate queued clicks cannot reuse a consumed display.
