The goal is a production-ready game. The core loop stays as settled. You re-present it, polish it and fill in what is missing. Use dedicated expert subagents and Workflow orchestration. Paths are relative to `horde-defense/` unless marked root.

## Context

That pass added: a paused first defense with a key legend, `Outcome::label` with a cause and tip, "Now open"/"New fronts" lines, a system crosshair, `desired_maximum_frame_latency = 1`, depth-scaled tree prices, and `crates/horde_core/examples/pacing.rs`.

- The settled loop, which the UI must end up matching exactly:
  1. New game, survivor, starting country, begin liberation. The first field opens paused.
  2. **Results** shows the outcome, cause or tip, what opened, coins, loot and an auto-sold summary. It has exactly three actions: **Upgrade**, **Try again / Next defense / Choose next country** (`continue_label`), and **Leave journey**.
  3. **Upgrades** offers **Back to battle** (`ContinueJourney`) and **Back to camp**.
  4. **Camp home** manages Mara, recruits, expeditions, outbreaks, equipment and briefing.
  5. Each liberation lets you recruit a defender. Mara or a recruit can take over the main run.
  6. Loot can be auto-sold by rule ("sell everything below green/Uncommon").
- Today Results and Upgrades share `ui/results.rs`. Camp has no home page. Recruits sit in the Operations tab, which unlocks behind `operations_available()` (`ui/navigation.rs:124`), and they can only run parallel expeditions. Auto-sell does not exist. Elites and affixes do not exist.

## Isolation rules

- Work in a new worktree and branch cut from local `main`. Never touch `C:\Projects\bevy-experiments`.
- Change files only under `horde-defense/`. Root files are off limits; if one is needed, stop and ask.
- Writing agents run one at a time in this worktree. Parallel agents are read-only.
- Use one `CARGO_TARGET_DIR`, cargo from PowerShell, and at most two cargo builders at once. The orchestrator serialises the debug, release and playtest builds, and verifiers queue behind them.
- PowerShell 5.1 only:
  - Never use `>`. Use `Out-File -Encoding utf8` or `git --output`.
  - Run native exes through `Start-Process` with redirected streams. `capture_review.ps1`, `measure_performance.ps1` and `verify_playtest.ps1` all break otherwise.
    - Amended by R24 (user, 2026-11-07; plan §2.4): `Invoke-Native` in `scripts/lib/Native.ps1` starts native children with `[Diagnostics.Process]::Start` and a `ProcessStartInfo`, UseShellExecute off and stdout and stderr redirected to the `.out.txt`/`.err.txt` logs. That form satisfies this rule, because in 5.1 `Start-Process -PassThru` can report a `$null` ExitCode once the child has exited (381e563). `>` stays forbidden, and a timeout still kills the tree with `taskkill /T /F`.
  - Fixing these scripts under `horde-defense/scripts` is allowed.
- No bare `git stash`. No push or merge. Ask before fast-forwarding local `main`.
- Ids never change. Content files are append-only. v1-v6 saves and old settings files must load.
- Settings: `bindings: [String; 8]` stays as it is. New actions go in separate serde-defaulted fields, with a test that loads an old 8-entry file.
- Rules are tested `horde_core` functions, changed only through `Game::apply(&Command)` with a typed `CommandError`. `horde_game` only renders. No widget does IO.
- TDD for core, egui harness tests for UI. Every new test must fail against the old behaviour.
- `--smoke` and GOLDEN keep passing. Every digest or `GAMEPLAY_TRACE` move needs a written reason and a deliberate re-bless.
- Balance changes need a reason backed by pacing and `--smoke` stats, before and after.
- Presentation never touches core RNG. No screen shake. Every audio warning has a visual twin. Reduced effects covers every new effect.

## Goals in priority order

   - Note that `review` is a default feature (`horde_game/Cargo.toml:26`). Playtest-profile numbers therefore include it, while the shipped `--no-default-features` build only gets a `--smoke` timing.
   - Build `BattleScreen` and `BattleViewModel` once per egui pass, enforced by a counting test.
   - Batch enemies, corpses and particles into a few meshes. Per-category caps live in a new `docs/PERF_BUDGET.json` with a test.
   - Extend `scripts/measure_performance.ps1`:
     - keep `peak` and `progressed-peak`, and add `stress` (17 lanes, late tiers, fire, MG and turret, a boss, night, a worker battle);
     - add `-Profile dev|playtest` and `-VsyncOff`;
     - honour `CARGO_TARGET_DIR`;
     - compare against the budget and exit non-zero when over.
   - Split `battle_view.rs`, `ui/battle.rs`, `art.rs` and `upgrade_graph.rs` along their seams. Rewrite `ARCHITECTURE.md` as an ownership table.
   - Measure the save clone with 1,000+ items and 3 workers. Make it cheaper if p99 is over 1 ms.
   - Acceptance:
     - With `-VsyncOff`, `progressed-peak` and `stress` show CPU (main plus render-world) p99 ≤ 10 ms and zero frames over 50 ms.
     - Interface mean at 225 enemies is at least 30% below the wave-0 baseline in the same profile and scene.
     - The pipelined-rendering decision is recorded with numbers.
2. **Post-run flow, camp and navigation**
   - Results and Upgrades each get exactly one amber primary action.
   - Camp home shows the roster with status, readiness and power (`Game::defender_power(defender, next_threat)`, tested), plus offers, expeditions, alerts and "Go to briefing". Operations and Mara become drill-downs. Remove every `{:?}` label.
   - Escape closes the topmost overlay, then goes Back: camp tab → Camp home → Upgrades/Results → Menu (with a confirmation). Construction mode follows decision 18. Test the full Screen x Tab x overlay matrix.
   - One "Save" label and a "Saved" toast. Save and load failures open a Retry / Open folder modal. Warn about an unapplied difficulty draft. The scale slider applies on release.
   - Battle:
     - the boss banner shows for at least 1.5 s, and a low-HP edge warning appears;
     - "Retreat & train" needs a hold or a confirmation;
     - the HUD stays at or below 2 rows at 1050x700@1.35;
     - construction mode no longer rescales the arena.
   - Onboarding: a one-time "New: X - find it in <tab>" callout, stage count and Mara timing at country choice, expedition notices, a core `SelectCountry`.
   - Acceptance: a headless test walks the whole loop: new game → Rook → country → defeat → Results → Upgrade → buy → Back to battle → victory → Next → liberation → Recruit → Back to camp → the recruit defends. Each step asserts the Screen, the Tab and one primary action.
3. **Defenders and campaign**
   - `Game::available_defenders()` and `Command::SetNextDefender`. `continue_journey` reserves the defender's loadout the way `deploy_survivor` does. The picker appears on Results and Briefing.
   - `SelectCountry` never creates an attempt. Outbreaks get "Plan response".
   - Recruit progression: the current cap is `12 + 8 * first_clears.len()` with 5 levels (`progression.rs:371`). Design picks a formula reaching 10 levels by the 6th liberation, tested.
   - Worker wins credit their `recruit_id`. Recruits get service history and an origin trait.
   - Exactly one notice per expedition outcome. Worker liberations get the "X liberated · N new fronts" line.
   - Acceptance (strategy profile, 20 seeds):
     - tests for persisting the defender choice, rejecting a reserved or guarding recruit, and idempotent `settle_parallel`;
     - liberations 2/4/10 and coins per minute reported;
     - parallel play frees 3-stage neighbours in at most 1/1.5 of the runs solo play needs;
     - fewer than 5 outbreak reopens over 10 liberations.
4. **Loot, items and auto-sell**
   - `Game::sale_eligibility` is used by `SellItem`, `sell_extras`, quotes and auto-sell. It excludes protected, locked, favourite, reserved, equipped, preset, recruit-equipped and npc_only items.
   - Route `Campaign::sell_unprotected`/`sell_quote` (`ledger.rs:90`) through it. A test shows the old filter selling a recruit-equipped item.
   - `AutoSellRule { enabled, sell_below, slots: [bool;4], keep_upgrades, apply_to_npc_runs }` with `Command::SetAutoSell`.
   - Auto-sell runs after the reservation is released, and for workers after `settle_parallel` remaps ids. No RNG. A checked wallet add keeps the item on overflow. Each item is sold at most once.
   - `Report.auto_sold` is a bounded receipt, and `RunRecord` gets the count and coins. Sale status shows only on Results, never in battle.
   - UI: an Auto-sell panel in Equipment with colour and text markers and a "would have sold N" preview. A Results loot block shows drops by quality, "better than equipped" with Equip, and "Auto-sold N · +C".
   - Items: content has 29 definitions, with 1 per slot at tiers 2-4. Add about 39 append-only ids so every tier 1-4 has one Ranged item per weapon class (6) and at least 3 of each other slot. Drops are weighted toward the current tier and the player's trained classes.
   - Acceptance:
     - `tests/auto_sell.rs` plus a property test: no guarded item is ever sold, and the quote equals the coins realised;
     - with the rule off, nothing moves;
     - parallel runs sell each item exactly once;
     - old saves load with the rule off;
     - the auto-sell profile stays within 1 run of baseline at tiers 1-3.

## Orchestration

- Each wave runs **Understand → Design → Implement → Review** with Workflow.
- Experts, one remit each: `ux-flow`, `campaign-defenders`, `loot-economy`, `progression-tree` (tree and skills), `enemy-balance`, `vfx-lighting`, `audio`, `perf-architecture`, `save-determinism`, `qa-captures`.
- **Understand:** parallel read-only auditors, citing file:line and measurements.
- **Design:** 2-3 designers per open choice, and a judge panel of 3 scoring against the invariants. Record rejected options.
- **Implement:** one writer at a time, TDD, one commit per finding.
- **Review:** parallel adversarial reviewers for correctness, saves and determinism, UI at both sizes, and perf. Repeat until a round finds nothing new.
- A completeness critic closes each wave. Nothing is done without a test, capture or number.
- Goals 2-8 are designed during waves 0-1. The schema in wave 1 is frozen only after every saved field from those designs is final. A field found later is serde-defaulted, or you stop and ask.
